# MaxLanding

Telegram-бот и мини-приложение для личного кабинета лендингов. Создание: шаблон и название. Страница поднимается на поддомене платформы, свой домен подключается A-записью.

## Что внутри

- Бот: создать ленд, примеры, логи, профиль, панель, поддержка. Если задан `WEBAPP_URL` с `https`, кнопки открывают мини-приложение.
- Запуск назначает адрес вида `ldng1.max.com`. Домен платформы и IP для A-записи задаются в панели.
- На карточке лендинга есть инструкция: A-запись своего домена на IP платформы. Когда запись совпала, страница открывается и по этому `Host`.
- Примеры — живые экраны шаблонов, по три на страницу. Магазина и баланса в кабинете нет.
- Логи пишут переходы, скачивания и обращения. Фильтры оставлены на следующий этап.

## Запуск

```bash
cp .env.example .env
npm install
npm run db:setup
npm run dev
```

API: `http://127.0.0.1:8787`. Мини-приложение в разработке: `http://127.0.0.1:5173`.

Локальный вход без Telegram есть только вне production: «Войти как админ» (`telegram id 10000`) и «Войти как пользователь». Токен бота лежит только в `.env` и в репозиторий не попадает.

Проверка и сборка:

```bash
npm test
npm run build
npm start
```

## Переменные

| Имя | Зачем |
| --- | --- |
| `BOT_TOKEN` | токен BotFather, включает long polling |
| `WEBAPP_URL` | https-адрес мини-приложения для кнопок бота |
| `APP_SECRET` | подпись сессий и шифрование токенов, от 16 символов |
| `ADMIN_TELEGRAM_IDS` | кто становится админом при входе через Telegram |
| `PUBLIC_BASE_URL` | ссылки, которые бот отдаёт на лендинги |
| `DATABASE_URL` | SQLite, файл `data/maxlanding.db` |

В панели задаются домен платформы, IP для A-записи и контакт поддержки.

Пока свой домен не делегирован, страница открывается по `/l/:slug` и по поддомену `ldngN.<домен платформы>`. После совпадения A-записи тот же лендинг отдаётся по заголовку `Host`.
